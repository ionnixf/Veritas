# ReserveWeek · работа команды

Общая ветка — **`main`**. Участник 1 объединяет готовые изменения и сдаёт проект. Участник 2 отвечает за сохранённые финальные ML-результаты и их аудит. Участник 3 готовит write-up и запись. [Что требует задание и что осталось](FINANCE_PLAN.md).

## Получить актуальный проект

На новом устройстве:

```bash
git clone https://github.com/ionnixf/Veritas.git
cd Veritas
```

В существующем клоне сначала `git status`, затем `git fetch origin`. Сохраните собственную работу отдельным коммитом в своей ветке перед переключением; чужие незакоммиченные файлы не удаляйте и не сбрасывайте. В чистом `main` обновление — `git pull --ff-only`. В существующей рабочей ветке включите общую версию через `git merge origin/main`. Конфликты разрешайте с сохранением обеих нужных частей.

Синхронизация второго устройства возможна после отправки общей версии в origin. При недоступной сети не считайте локальные `origin/*` свежими: передайте SHA и файлы изменений участнику 1.

## Запустить задания

Модель и режим рассуждения выбирает человек в клиенте до отправки. Исполняемый Markdown содержит только задачу; он не меняет настройки модели.

| Участник | Файл | Результат |
|---|---|---|
| 1 · приёмка и интеграция | [01-codex-demo.md](../prompts/next/01-codex-demo.md) | Проверенное готовое демо и общая версия |
| 2 · приёмка ML | [02-codex-ml.md](../prompts/next/02-codex-ml.md) | Аудит сохранённых test-артефактов и итогового вывода |
| 3 · текст и видео | [03-deepseek-video.md](../prompts/next/03-deepseek-video.md) | Репетиция готового сценария и запись |

После синхронизации отправьте в соответствующий чат одну строку:

```text
Прочитай prompts/next/01-codex-demo.md и полностью выполни задание.
```

```text
Прочитай prompts/next/02-codex-ml.md и полностью выполни задание.
```

Для чата без доступа к репозиторию прикрепите `03-deepseek-video.md` и по возможности `docs/VIDEO_SCRIPT.md` и отправьте: «Полностью выполни задание из прикреплённого Markdown-файла». Самодостаточный файл можно использовать с любым текстовым помощником. Укажите реально использованный инструмент в credits.

## Объединение и передача

Новые задачи начинаются от актуального `origin/main` в одной рабочей ветке на участника. Для аудита ML создайте новую рабочую ветку от `origin/main`; старую ветку финального запуска возобновлять не нужно. Готовые изменения отправляйте своей веткой и PR с **base = main**. Не переписывайте историю общей ветки. Участнику 1 передайте ссылку/патч, SHA, команды и результат проверки.

Владение: участник 1 — `demo/`, `data_pipeline/`, общие документы и интеграция; участник 2 — `experiments/`, `artifacts/`; участник 3 — содержимое write-up и записи. Черновик итогового текста — `submission/SUMMARY.md`, готовый сценарий — `docs/VIDEO_SCRIPT.md`; их можно перенести в обычный документ.

CSV: одна строка — дата решения `as_of`, суммы в GBP. `model_q80` — модельный резерв, `training_q80` — постоянный train-Q80, `actual_gbp` — зарегистрированные отмены следующей недели. Дефицит — `max(actual_gbp - model_q80, 0)`, остаток — `max(model_q80 - actual_gbp, 0)`. Схему сохраняем. Общие метрики берём из JSON, не пересчитываем в интерфейсе.

Демо уже готово: `python3 -m demo.app`, затем http://127.0.0.1:8000. Пройти 4 апреля и 18 января, проверить раскрытие и сброс результата. [Действия для записи](../demo/README.md).

До сдачи участник 1 проверяет доступность кода и write-up без входа и подтверждение отправки формы. Срок — **16 ноября 08:59 Самары**, видео до двух минут необязательно. Test уже раскрыт в двух параллельных ветках; используем канонические результаты `codex/ml-final`. Проверяем их аудитом, не повторным подбором модели.
