# ReserveWeek · старт на двух устройствах

Оба чата получают одну версию проекта из Git. Ветки для работы растут из `codex/team-start`, сюда же направляем первые PR. Участник 1 отвечает за интеграцию. Если у второго GitHub-аккаунта нет права записи, владелец может добавить его как collaborator, либо участник 2 отправляет PR из своего форка в ту же базовую ветку.

## Открыть проект

На первом компьютере продолжайте в текущей папке Veritas. На втором устройстве достаточно клонировать общую базу и открыть папку Veritas в своём Codex. Каждый использует собственные учётные записи.

```bash
git clone --branch codex/team-start https://github.com/ionnixf/Veritas.git
cd Veritas
```

Если репозиторий уже есть, откройте его и выполните `git fetch origin`. В каждом клоне создайте **только свою ветку**, командой из соответствующего задания. Если возобновляете работу, используйте `git switch ИМЯ_СВОЕЙ_ВЕТКИ`.

Используй имеющийся CSV, интерфейс должен работать без ключей и интернета. Реализуй в demo/, предпочтительно на стандартном Python и обычном HTML с одной командой запуска; добавь её в demo/README.md. ## Участник 3 · первые 60 минут

1. Сразу запусти из корня `python3 -m demo.replay 2011-01-18`, затем ту же команду с `--reveal`. На Windows подойдёт `py -m demo.replay 2011-01-18`. Для этого уже есть данные и достаточно стандартного Python.
2. За первые 20 минут подготовь английскую озвучку на 3 фразы: кто принимает решение, сколько предложил оставить инструмент, что случилось после. DeepSeek по желанию сокращает черновик; числа бери из CSV. Дату, прогноз, факт и разницу сверь с CLI.
3. Когда появится экран из первой ветки, пройди оба сценария и запиши дубль на 20 секунд. Передай участнику 1 один конкретный отзыв. Сценарий и write-up принадлежат тебе; если Git неудобен, пиши в обычном документе, участник 1 перенесёт текст в submission/. Подписка Codex для этой роли не нужна.

## Контракт и объединение

Одна строка CSV — дата решения `as_of`. Все суммы в GBP. `model_q80` — предложенный резерв, `training_q80` — постоянный резерв из train. `actual_gbp` раскрываем по кнопке. Дефицит равен `max(actual_gbp - model_q80, 0)`, остаток — `max(model_q80 - actual_gbp, 0)`. Значения читаем из строки выбранной даты. Общие метрики берём из artifacts/validation_metrics.json. Участник 1 владеет demo/, data_pipeline/ и общими файлами, участник 2 — experiments/ и artifacts/, участник 3 — содержанием submission/.

После рабочего коммита каждый отправляет свою ветку командой `git push -u origin HEAD` и открывает PR с **base = codex/team-start**. В описании оставьте команду запуска, результат и идентификатор коммита. На следующем устройстве и в новом чате этого достаточно для продолжения. Участник 1 объединяет готовые PR, проверяет запуск экрана и replay на объединённой версии. Для следующей задачи обновите свою ветку командами `git fetch origin` и `git merge origin/codex/team-start`. Перед сдачей участник 1 переносит проверенную версию в main через PR.
